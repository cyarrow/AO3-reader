# AO3 Reader — 需求文件（草案 v0.1）

## 1. 問題與目標

- **問題**：在手機瀏覽器看 AO3，閱讀體驗不夠舒適（排版、字體、進度、離線都受限）。
- **目標**：做一個 Android 原生閱讀器，用來瀏覽、搜尋、閱讀 AO3 作品，並可登入帳號。**最重視閱讀的舒適度。**
- **使用者**：自己（側載 APK，不上架 Google Play）。
- **介面語言**：中英雙語（跟隨系統語言）。

## 2. 限制與前提

| 項目 | 說明 | 對策 |
|---|---|---|
| AO3 沒有官方 API | 只能抓取網頁 HTML 再解析 | 解析層獨立成一個模組，網站改版時只需修改這一層 |
| 有頻率限制（HTTP 429） | 請求太頻繁會被暫時封鎖 | 全域限速、讀取 `Retry-After` 標頭、做本地快取 |
| 登入 | 沒有 OAuth，需要模擬網頁表單登入 | 只保存登入 cookie（加密），不保存密碼 |
| 成人內容 | 未登入時預設跳出警告頁 | 加上 `view_adult=true` 參數，並提供設定開關 |
| 不上架 | 不受 Google Play 政策限制 | 透過 GitHub Releases 或 Actions 產出 APK |

## 3. 功能範圍

### 第一版（MVP）
**A. 閱讀器（最高優先）**
- 上下捲動與左右翻頁兩種模式，可切換
- 字體（內建幾套中英文字體，可匯入自訂字型）、字級、行距、段距、左右邊距、文字對齊
- 主題：亮色、暗色、純黑（AMOLED）、羊皮紙，並可自訂文字與背景顏色
- 記住閱讀進度（精確到段落位置），在章節列表標示已讀章節
- 章節目錄、上一章與下一章、可切換顯示全文（Entire Work）
- 閱讀中保持螢幕常亮、調整亮度、全螢幕沉浸模式、音量鍵翻頁
- 顯示作者註（Notes）、摘要、尾註，並可摺疊
- 長按選取文字後複製

**B. 瀏覽與搜尋**
- 首頁：最近閱讀、書架、Fandom 分類入口
- Fandom、標籤作品列表
- 進階搜尋與篩選：分級、警告、類別、語言、完結狀態、字數、排序；可排除特定標籤
- 作品卡片：標題、作者、標籤、摘要、字數、章數、Kudos、更新日期

**C. 帳號**
- 登入與登出（保存加密的 cookie）
- 按 Kudos、加書籤、Marked for Later
- 瀏覽自己的書籤、閱讀紀錄、訂閱

**D. 離線**
- 下載作品到本地（使用 AO3 提供的 HTML 下載或逐章抓取），統一用同一個閱讀器開啟
- 本地書架：管理已下載作品、檢查是否有新章節

### 第二版之後（候選）
- 訂閱更新通知（背景定期檢查新章節）
- 留言：閱讀與發表
- 本地標籤封鎖（Muting）：自動隱藏不想看的標籤、作者、跨過多 fandom 的作品
- 閱讀統計：閱讀時間、字數
- 本地書籤與畫線筆記
- 文字轉語音（TTS）朗讀
- 匯出 EPUB
- Collections、Series 頁面
- 平板雙欄排版
- 收件匣（Inbox）、個人頁面

### 不做
- 上傳或編輯自己的作品（使用頻率低、風險高）
- 大量爬取或批次下載（會違反 AO3 的使用規範）

## 4. 非功能需求
- 最低支援 Android 8.0（API 26）
- 閱讀頁面開啟要快：已快取的章節在 300ms 內顯示
- 網路錯誤、429、AO3 維護時，畫面要友善提示，並允許重試
- 隱私：沒有任何追蹤或分析程式，資料只存在本機

## 5. 技術選型（建議）
- Kotlin、Jetpack Compose、Material 3
- 網路與解析：OkHttp（含 CookieJar）、Jsoup
- 本地資料：Room（作品、章節、進度、下載）、DataStore（設定）
- 架構：MVVM、Repository；手動依賴注入（AppContainer），App 規模小，不引入 Hilt
- 閱讀器：Compose 原生排版，翻頁模式自行分頁（不使用 WebView，閱讀體驗較能控制）
- 建置：Gradle，搭配 GitHub Actions 自動產出 APK

## 6. 中文閱讀
- **簡轉繁**：用 OpenCC 做離線字元轉換（不是 AI 翻譯）。偵測到簡體作品時自動轉成繁體，每部作品都可以個別關閉；可另外選擇是否把用詞也轉成台灣慣用語（例如「軟件」轉成「軟體」）
- **字型**：APK 只內建一套同時涵蓋簡繁的字型，其他字型（思源宋體、霞鶩文楷、芫荽、思源黑體等）在 App 內下載
  - 設定頁可以即時預覽同一段文字，方便比較字型
  - 可調整字重（目前的細黑體太細、難讀）
  - 也可以匯入自己的字型檔
- 中文排版：段首縮排（可開關）、標點擠壓、行距預設偏寬

## 7. 建置與更新
- GitHub Actions：每次 push 都建置 debug APK；打上 `v*` tag 時，建置已簽章的 release APK 並發佈到 GitHub Releases
- 簽章：release keystore 以 Base64 編碼存成 GitHub Secrets（每次都用同一把金鑰，App 才能覆蓋安裝更新）
- App 內更新：啟動時（或在設定頁手動）查詢 GitHub Releases 的最新版本，比對 versionCode；有新版就下載 APK，並交由系統安裝程式安裝（需要 `REQUEST_INSTALL_PACKAGES` 權限）

## 8. 開發階段（閱讀器優先）
1. **M0 專案骨架**：Gradle、Compose、CI 建置、Release 流程、App 內更新
2. **M1 閱讀器與搜尋**：內建搜尋（使用者要求提前）與作品頁；完整閱讀設定；兩種閱讀模式；記住閱讀進度；簡轉繁；字型管理；快取
3. **M2 瀏覽**：Fandom 與標籤列表、點標籤搜尋
4. **M3 帳號**：登入、Kudos、書籤、Marked for Later、閱讀紀錄、訂閱
5. **M4 離線**：下載、本地書架、檢查新章節
6. **介面檢視**：第一版完成後，在開發環境安裝 impeccable，搭配 ui-ux-pro-max 檢視並改進介面設計，以閱讀舒適度和好用程度為最高優先
7. 之後：依使用心得持續打磨閱讀器，再考慮第二版候選功能

## 9. 已確認決策
- 自己使用，側載安裝，不上架
- MVP 功能：瀏覽與搜尋、閱讀器、登入、離線下載
- 閱讀模式：上下捲動與左右翻頁，可切換
- 介面語言：中英雙語
- 用 GitHub Actions 建置，App 內自動檢查並更新
- 開發順序：閱讀器優先；第二版候選功能先不提前，資源集中在閱讀器打磨
- 簡體作品自動轉繁（OpenCC），每部作品可個別關閉
- 字型：內建一套，其他在 App 內下載
- 簽章金鑰由開發端產生，使用者自行存進 GitHub Secrets（不進 repo）

## 10. 實作備註
- 作品內容透過 AO3 的「下載 HTML」取得：先抓作品頁找到下載連結，再下載完整 HTML（一部作品兩次請求，結構穩定，也方便離線）
- 所有請求排隊，並且至少間隔 1.5 秒
- 測試用的真實作品 HTML 不進 repo（版權考量）；需要時用 `-PlocalFixtures=<目錄>` 在本機測試
- 介面截圖：`./gradlew testDebugUnitTest --tests '*ScreenshotTest*' -Pscreenshots`，輸出在 `app/build/outputs/screenshots/`
